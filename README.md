# L3X

A confidential order-book exchange rollup on Aztec. [`SPEC.md`](SPEC.md) is the design. This repository holds phase P0 (SPEC.md §15): the `rollup-on-aztec` proof pipeline ported to Aztec v6, with a merge tree, a role-partitioned VK tree, and a Bridge contract that settles batches under a delayed configuration. Phase P1, a single-market exchange, is under way.

Toolchain: Aztec **6.0.0** (`.aztecrc`), installed with `aztec-up`, with its bundled `aztec-nargo` (Noir 1.0.0-rc.3) and `aztec-bb`. The scripts run on Node 24, which executes the TypeScript directly, and use the `@aztec-labs` 6.0.0 packages from npm. The spec targets 6.1.0, but neither the installer nor npm publishes its toolchain yet. The v6.0.0 proof-type and size constants match those checked for v6.1 in SPEC.md §3.

## Layout

| Path | Contents |
| --- | --- |
| `circuits/l3x_types` | Shared constants, Poseidon2 sponge, running values and node output, VK tree, DA sponge, `BatchHeader` |
| `circuits/client_auth` | P-lane client circuit: knowledge of the secret behind an account's auth binding, authorizing `msg` |
| `circuits/agg_app` | Chonk app: verifies 10 client proofs against the pinned client VK and folds the first `count` |
| `circuits/{init,tail,hiding}_kernel` | IVC kernels: OINK, HN, HN_FINAL, each pinning its predecessor's VK hash |
| `circuits/tube` | P-segment leaf: verifies the Chonk proof against the pinned Chonk VK and applies the segment's effect |
| `circuits/x_segment` | X-segment leaf (P0 stub): one L3 block; advances time, consumes priority entries, absorbs DA |
| `circuits/padding` | Identity segment, so a single-segment batch still gives the root two children |
| `circuits/merge` | Verifies two merge-tree nodes against the VK tree, checks they chain, outputs the combined transition |
| `circuits/root` | Top merge: closes IPA, binds the batch header, outputs `H(header)` |
| `circuits/agg_ultra` | M1 measurement: `agg_app`'s checks in plain UltraHonk |
| `circuits/rogue_app`, `circuits/rogue_segment` | Adversarial fixtures for the VK tests; never deployed |
| `circuits/vendor/bb_proof_verification` | Vendored from aztec-packages v6.0.0 (Apache-2.0) |
| `contracts/bridge` | `L3XBridge`: priority queue, `settle` (private verify) → `_apply` (public checks), delayed upgrades, TXE tests |
| `scripts/src` | `build.ts`, `prove.ts`, `vk_substitution.ts`, `settle.ts`, `m1.ts`, and `pipeline.ts` (the batch prover) |
| `scripts/out` | Generated: VK manifest, batch, measurements and settlement reports (git-ignored) |

`*/src/pinned.nr` files are generated by `build.ts` and are not hand-edited.

## Running

```bash
aztec-up install 6.0.0
```

```bash
cd scripts && npm install
```

```bash
npm run build:circuits
```

The build compiles in dependency order, pins each fixed child's VK hash into its parent, and builds the VK tree. It writes `scripts/out/manifest.json`, which includes the VK tree, the configuration hash and the root VK hash.

```bash
npm run prove
```

This proves one synthetic batch natively, `root(merge(tube, x), x)`. It writes `scripts/out/batch-1.json` and `scripts/out/measurements.json`.

```bash
npm run vk-substitution
```

This runs the negative tests: a rogue IVC app, rogue segments outside the VK tree or in a borrowed slot or the wrong role, segments that do not chain, and a segment under another configuration. All must be rejected.

```bash
npm run m1
```

This compares aggregating 10 client proofs through Chonk and the tube with doing it in plain UltraHonk. It writes `scripts/out/m1.json`.

```bash
npm run settle
```

This runs the P0 exit test and measurement M5 on an in-process 6.0.0 local network, with real client-side proofs. It writes `scripts/out/settlement.json`.

```bash
cd contracts && aztec compile && aztec test
```

This compiles the Bridge and runs its TXE tests.

## P0 status

Complete. See SPEC.md §14 for the measured numbers and §15 for the summary.

| Item | State |
| --- | --- |
| G1: tube → merge → root → contract | Done. Merges verify RollupHonk children; the root closes IPA; the root proof is UltraHonk ZK. |
| G2: VK pinning | Done. The Chonk chain and the tube pin constants; merges and the root check the role-partitioned VK tree, whose root the configuration commits to. Seven substitution and role tests rejected. |
| G3: Bridge state | Done (P0 subset): state root, batch number, priority queue with `T_force`, time bounds with `T_lag`, DA hash, replay protection, and the operator, root VK and configuration as `DelayedPublicMutable` with a 21-day delay. 24 TXE tests. |
| G4: shape | Done: any number of segments, merged pairwise; padding for one segment; P- and X-segments mixed. The client subtree has one circuit, pinned in `agg_app`. |
| G5: v6 constants | Done for 6.0.0; Chonk proof length and layout checked at runtime. |
| M1, M4, M5, M7 | Measured. M1: Chonk is 5.3× faster than UltraHonk recursion for 10 client proofs. M5: the network admits at most 1,714 DA fields per settlement on the local network, well below the 4,096-field log cap. |
| P0 exit test | Passed on a 6.0.0 local network with the PXE prover and node `realProofs` on. Two priority requests were queued. Batch 1 was `root(merge(tube, x), x)` over a P-segment and two X-segments that consumed those requests. It settled through a client-proved transaction, the on-chain tip matched the header, and the DA log matched the proved payload. Negative checks: a replay is rejected by `_apply` ("stale state root"). A forged header that passes every public check, paired with batch 1's proof, is rejected while the settlement transaction is proved. Batch 2 carried the largest admissible payload. |

## Caveats

- The local network settles epochs synthetically, so a receipt status of `proven` there does not mean an epoch proof was verified. What is real in `settle.ts`: the settlement transaction's client-side Chonk proof, which includes verifying the root proof in-circuit, and the node's check of transaction proofs (`realProofs`).
- TXE does not prove, so the Bridge's TXE tests use a dummy root proof; the proof binding is tested in `settle.ts`.
- Timings come from one laptop run each and are not benchmarks.
- The P0 auth circuit, the tube's effect and the X-segment stub stand in for real exchange logic.
